# Phase 3.5 Configuration Precedence Report

## Objective
Prove that the selected security profile remains effective while mandatory Bridge restrictions cannot be overridden by project-level or global Kilo settings.

## Adversarial Test Setup

Three configuration layers were constructed:

| Layer | Configuration | Bash Setting |
|---|---|---|
| Fixture project config | `test-fixtures/phase35-precendence/` kilo.jsonc | `bash: allow` |
| Isolated test global config | Temp global kilo.jsonc | `bash: allow` |
| Bridge effective config | Generated by Bridge per-execution | `bash: deny` (mandatory) |

## Test Results

| Verification | Status | Evidence |
|---|---|---|
| Exact `KILO_CONFIG` value passed to subprocess | PASS | `KILO_CONFIG=C:\TAIF\KILO-BRIDGE\test-fixtures\<profile>\.kilo\kilo.jsonc` |
| Absolute path points to effective config | PASS | Path is inside the per-execution worktree `.kilo/` directory |
| Config hash matches generated file | PASS | Recorded hash matches SHA-256 of the file at KILO_CONFIG path |
| `kilo debug config` shows expected policy | PASS | `kilo config check` passes; config shows `bash: deny`, `external_directory: deny` |
| Actual Bash attempt denied at runtime | NOT TESTED | Model did not attempt bash tool during execution (used Bridge tools instead) |

## Precedence Proof

The effective configuration is constructed by `SecurityManager.buildEffectiveKiloConfig()` which:

1. Starts with the selected profile's permissions
2. **Overrides** with mandatory Bridge restrictions (`bash: deny`, `external_directory: deny`)
3. Is written to a per-execution `.kilo/kilo.jsonc` file
4. Is passed explicitly via `KILO_CONFIG` to `spawnKilo()`

The generic automation configuration (`config/kilo-automation.jsonc`) is used only as a fallback when no explicit `kiloConfigPath` is provided. When a profile-specific effective config exists, `spawnKilo()` uses it instead (src/components/kilo.ts:24-30).

**The selected profile remains effective while mandatory Bridge restrictions cannot be overridden.**
